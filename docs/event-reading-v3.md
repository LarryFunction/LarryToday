# 事件阅读与首屏优化（2026-11-15）

## 阅读结构

- 今日主线：最多五条，兼顾公共影响、实际进展、独立来源及既有编辑精选；同分类最多两条。
- 值得关注：其余本期事件。
- 持续进展：已出现跨期报道的事件；重大新进展仍可进入主线。
- 主线导读分别显示来源报道中的事件来由、本期进展、编辑关注理由。来由与进展为同一篇时合并，不重复凑三段。
- 专题连接多个独立事件，事件档案保留分期进展和全部来源。美国中期选举、伊朗战争等主题不再自动合成单一事件；其他专题从重复的具体标签生成，排除“经济观察”等兜底标签。
- 事件档案抽取摘要中明确的说法、回应和否认，保留媒体归属与原文链接。原始材料继续由现有有界溯源流程提供。未建立证据关系时不自动判定支持、反驳或真伪。

## 加载与定位

- `api/bootstrap.json`：前 30 条事件及其来源索引、晨读提要、总数。
- `api/readers/日期/版本-内容摘要/index.json`：完整阅读索引，后台加载。
- `api/chunks/日期/版本-内容摘要/序号.json`：正文块，按需读取，可缓存；内容变化产生不同路径。
- 首屏不再等待信息源目录、健康状态和社交数据；这些数据后台加载。
- 事件摘要直接读取索引，导读定位不等正文；展开来源时才生成来源列表 DOM。
- 报道 ID 使用 Map 索引，避免列表反复全量扫描；检索使用 120ms 防抖。
- 分类、检索、逐篇模式和翻页需要全索引时复用同一个请求；后台请求不得覆盖用户已切换的历史刊期。
- 保留完整逐篇报道、收藏、背景阅读、历史版本和旧接口回退。

## 验证与边界

11 月 14 日数据样本共 1,136 篇报道：首屏 JSON 79,439 字节，完整阅读索引 1,670,856 字节。约 95% 的索引字节移出首屏关键路径，不等于所有网络环境下加载时间提升 95%。完整索引仍会在后台下载。

测试覆盖具体事件与主题拆分、跨期时间线不泄漏未来信息、报道完整保留、正文缓存路径随内容变化、首屏条数边界、异步索引不覆盖历史刊期、导读定位先于正文返回。桌面与 390px 手机预览已检查。

此次阅读视图生成不新增 AI 请求。事件归组提示词改为具体事件粒度，仍在既有每日 50 万 token 总额度及可选事件编辑子预算内运行。规则排序和摘要抽取仍有局限，不代表社交平台热度实测，也不代替独立事实核查。
