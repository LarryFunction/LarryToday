# 每日出版与维护

## 出版时刻与失败保护

每日按北京时间 07:00 截稿，GitHub Actions 计划在 07:17 执行，08:47 补跑一次。GitHub 定时任务可能排队，不能保证准点；前一次已出版时补跑跳过，不调用 AI。任务固定目标刊期，不会因执行跨越截稿时间而改变刊期。

本期窗口内没有新闻时不出版，保留上一期。背景资料不能单独组成新一期。AI 故障时发布原始标题和摘要；社交平台采集故障不阻断主要新闻出版。刊期与页面当前日期分开显示，旧期标注“往期日报”。

## 更新报告与失败提醒

每次出版产生 `data/update-report.json` 和 `data/update-report.md`。GitHub 仓库的 Actions → Daily newspaper → 对应运行，可直接看到中文 Summary，以及保留 30 天的 publication-report 附件。失败时报告尽量保存失败阶段、错误类型及保留的刊期，不记录 API 密钥或完整异常文本。成功报告随新闻数据提交；失败报告保留在 Actions 附件中，不替换线上日报。

报告包括抓取／收录篇数、实际来源数、事件数、合并数、AI 缓存命中、新处理、失败、未处理、各阶段 token、预算核算量和国别识别覆盖篇数。没有供应商用量时显示“未提供”，不能视为零。发布失败使工作流失败，可使用 GitHub 原生 Actions 失败通知；请在个人 GitHub 通知设置中启用 Actions 邮件或站内通知。系统没有额外接入邮件或短信服务。

`published` 表示成功；`degraded` 表示部分来源／AI 未完成但已有可读日报；`failed` 表示出版失败；`skipped` 表示本期已出版，没有重跑。预算耗尽保留全部新闻并记录剩余未编辑数。

## 同事件与多来源阅读

AI 已确认的同事件分组优先。另用免费规则合并至少 24 个字母／汉字的相同标题（忽略空白与标点），且要求不同来源、同板块、同内容类型、相同地域集合、时间相隔不超过 12 小时。每个成员须和已有成员直接匹配，防止链式合并。

规则分组显示“同题报道”，AI 确认分组显示“同一事件”，展开后保留每家来源与原文。来源数量不意味着独立核实，同通讯社转载也可能出现。标题不同或新增数字、进展的报道不会仅凭主题相似就合并。原有 AI 比较预算和缓存不变，不为提升合并数量增加无上限调用。

最新阅读索引应用新的分组规则，并更新晨读跳转；历史初版文件不覆盖。仅改变列表组织，不删除来源文章。
