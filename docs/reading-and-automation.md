# 阅读优化、AI 成本与每日自动出版

更新日期：2026-10-21。

## 阅读方式

最新日报使用 `api/reader.json` 索引和每份最多 30 篇的正文块。前端每页显示 30 个事件，分类、搜索和精选仍在全刊索引上进行；切换筛选回到第一页。晨读链接会跳到目标事件所在页。多源事件会一并加载关联报道，因此一页可能请求多个数据块。历史版本继续使用完整快照，但也分页渲染。索引保留可搜索摘要文本，因此并非零成本下载；原始长摘要和正文内容按需读取。

国家/地域标注仅根据标题、摘要中的明确词语匹配，优先采用标题，不按媒体所在地推断。国家字典为保守的中英文常见国家集合，不是全球实体识别系统；未覆盖的名称显示“未明确地域”。单国、双国、多国、全球、区域、研究和太空各有稳定印记。标注说明可悬停查看；它不是国籍、主权或媒体立场判断。

## AI 成本控制

- 原有文章缓存继续复用，不批量重做已编辑新闻。
- 常规文章一次生成标题、概述和标签；来源和类别多样性优先的重点文章再复核。
- 不再因为整批格式异常，将六篇逐一重新生成和复核。
- 多源比较先按标题词汇和 48 小时时间邻近筛候选，再由模型确认同一事件。候选组分别缓存，避免某一篇新增导致全刊比较缓存失效。这是保守筛选，可能漏掉措辞差异很大的同一事件。
- 存在跨源候选时先为比较阶段留出20%预算。预算不足时保留所有原始报道，以原题和来源摘要展示；不减少新闻数量，不伪装已完成 AI 编辑。

可在本机 `.env` 或 Actions Variables 设置：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `AI_TOKEN_BUDGET` | `300000` | 单次 enrich 的请求预留预算，所有生成、复核、比较及重试共享 |
| `AI_REVIEW_LIMIT` | `12` | 新处理文章中额外复核的重点文章数 |
| `AI_COMPARISON_LIMIT` | `12` | 本次最多比较的候选事件组 |

发送前按请求 UTF-8 字节数、协议余量及最大输出预留预算；成功返回 `usage` 后按供应商报告结算。失败或缺少 usage 的请求保留预留额，避免把不明消耗当作免费。由于供应商 tokenizer、隐藏推理或计费规则可能不同，这不是精确账单或供应商侧硬限额。请同时设置供应商预算。极低预算可能不足以发起一个批次；预算为零不发送生成请求。

`data/ai-usage.json` 和日报 `ai_status` 包含分阶段调用、重试、输入/输出 token、缓存命中、剩余文章和预算耗尽状态。不记录密钥、完整请求或响应。`--ai-limit` 仍可限制新编辑数量，但不能替代总预算。

此次实现未调用真实付费 AI，不能在没有实际账单的情况下承诺节省百分比。

## GitHub Actions 每日出版

`.github/workflows/daily.yml` 每天北京时间 **07:17** 尝试出版，保留 07:00 截稿窗口。也可在 Actions → Daily newspaper → Run workflow 手动执行。已存在当日刊期时直接跳过，不花费 AI 额度，不自动修订。

第一次使用前：

1. 把此次代码推送到 `main`。
2. 在 Settings → Secrets and variables → Actions → Secrets 添加 `BASE_URL`、`BASE_KEY_1`、`BASE_KEY_2`、`BASE_KEY_3`。不要上传 `.env`。
3. 在 Variables 设置 `AI_ENABLED=true` 才启用云端 AI；未设置时每日照常采集出版原始报道。
4. 按上表设置预算，可选设置 `AI_MODEL`。
5. 确认仓库允许该工作流以 `contents: write` 提交已发布数据；如果分支保护禁止机器人直接推送，需要调整发布流程后才能自动保存，不要强推绕过保护。
6. 手动运行一次，检查 AI 用量、日期和 Pages 部署结果。

工作流会缓存 AI 结果和素材池，提交已发布新闻，然后显式调用 Pages 部署工作流，因为机器人通过 GITHUB_TOKEN 推送不会自动触发普通 push 部署。见 [GitHub GITHUB_TOKEN 文档](https://docs.github.com/en/actions/concepts/security/github_token)。

缓存不是永久备份，可能被淘汰；缓存丢失时预算仍有效，但命中率会下降。初次云端运行不会自动拥有本机 AI 缓存。不要把密钥放进缓存。当前工作流每天采集一次，短保留时间的 RSS 仍可能遗漏日内早些内容；更高频素材收集可以后续增加。

GitHub 定时任务可能延迟，公开仓库长期无活动时可能被停用；它不是准点出版服务。参见 [GitHub 定时事件说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)。

定时任务并发串行；如果更新期间有人推送，机器人推送可能失败，工作流会报错而非强行覆盖。先拉取并核对版本，再重试。出版后会明确运行 Pages 构建，不能只根据数据提交成功判断页面上线成功。

## 日常验证

```powershell
python -m unittest discover -s tests
node --check public/app.js
python scripts/build_pages.py
python -m http.server 8010 --directory dist
```

浏览 `http://localhost:8010` 检查分页、跨页搜索、晨读定位和收藏。不要在测试期间运行付费更新来代替界面验证。
